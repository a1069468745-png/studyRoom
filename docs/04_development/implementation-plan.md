### 1.5 阶段 4 并行执行原则

- 阶段 4 执行方式调整为“后端泳道 + 前端泳道 + 契约治理泳道”并行推进，不再采用“前端整体等到 DEV-008 再开始”的串行口径。
- 前端泳道自 `DEV-001` 起即可基于 `docs/03_design/api-spec.md`、统一错误结构、任务状态结构和权限边界说明开展页面骨架、API client 与 mock/stub 开发。
- 前端工程默认采用 Vue + TypeScript + Vite + Vue Router + Pinia + Axios + Element Plus，详细约束以 `docs/03_design/frontend-architecture.md` 为准。
- 后端泳道继续按 `DEV-001` 至 `DEV-007` 的业务与基础能力顺序推进，但每次对数据模型、权限模型或 API 契约的修改，都必须同步触发契约回归和前端 mock 更新。
- `DEV-008` 的角色从“前端首次联调”调整为“前后端闭环收口与端到端验收”，用于汇合并行成果，而不是前端开发起点。
- 当前仓库和会话环境未发现项目级 `agent-teams` 机制，因此阶段 4 采用“多个 agent 人工编排协作”的方式推进：协调 agent 维护单一规划口径，后端 agent、前端 agent 并行推进，QA/契约 agent 负责契约和回归校验。
- 阶段 4 每个 `DEV` 的真实执行，统一受 `ai/state04/stage-4-development-execution-prompts.prompt.md` 约束；该 Prompt 先检查阻塞 TODO、阶段收口项、依赖完成度和测试计划，检查不通过时禁止编码。
- 若某个 `DEV` 的门禁检查不通过，默认下一动作不是“等待”，而是优先补齐与当前阶段直接相关的待办、决策、风险、契约或测试计划缺口，直到重新满足准入条件。

## DEV-001：后端微服务工程基座

### 1. 阶段目标

建立首批后端服务与公共模块的最小工程基座，为后续数据、权限和业务能力提供统一入口。

### 2. 阶段范围

#### 本阶段包含

- 后端 Maven 多模块父工程。
- `gateway`、`auth-service`、`knowledge-service` 首批服务骨架。
- `service-common`、`web-common`、`security-common`、`testing-common` 公共模块。
- 统一健康检查、错误模型、traceId 与基础测试样例。
- 支持前端并行启动所需的统一错误结构、任务状态结构和接口调用基线。

#### 本阶段不包含

- 全量业务逻辑。
- 数据库 schema 与迁移细节。
- 真实权限规则与资源归属判定。
- 完整前端业务闭环与三角色真实接口验收。

#### 并行协作说明

- 本阶段允许前端基于已冻结契约并行建立工程壳层、路由骨架和 mock/stub 基座。
- 本阶段不要求前端完成真实业务闭环，但要求后端交付足以支撑前端先行开发的统一错误和任务契约。

### 3. 前置条件
