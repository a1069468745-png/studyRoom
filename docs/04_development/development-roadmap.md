## 路线图

1. `DEV-001`：后端微服务工程基座
2. `DEV-002`：数据模型与迁移基座
3. `DEV-003`：认证与权限基础能力
4. `DEV-004`：知识库与题库最小闭环
5. `DEV-005`：规则模板与组卷后端
6. `DEV-006`：考试与批改主链路
7. `DEV-007`：分析与视频解析闭环
8. `DEV-008`：前端闭环收口与端到端验收
9. `DEV-009`：安全、异常与回归补强
10. `DEV-010`：可观测性与发布准备

## 关键原则

- 先规划、后实现。
- 先冻结契约，再以前后端双泳道并行推进。
- 先主链路，后增强能力。
- 前端自 `DEV-001` 起基于契约和 mock/stub 开始，不等待全部后端完成。
- 先明确数据与权限，再做真实联调闭环收口。
- 每阶段必须可独立验证、可独立审查、可独立回滚。

## 执行泳道

- 后端泳道：`DEV-001` 到 `DEV-007` 按服务边界推进基座、数据、权限和业务能力。
- 前端泳道：自 `DEV-001` 起并行推进双端壳层、路由、API client、mock/stub 和页面骨架。
- 契约治理泳道：自 `DEV-001` 起维护 API 契约、错误结构、任务状态和联调差异清单。
- 汇合点：`DEV-008` 负责把前后端并行成果收口为三角色主链路 E2E 验收结果。

## 多 Agent 协作

- 当前仓库未定义项目级 `agent-teams` 机制，阶段 4 默认采用多个 agent 人工编排协作。
- 协调 agent 负责规划与冲突处理；后端 agent 和前端 agent 并行推进；QA/契约 agent 负责契约和回归。
- 若后续要正式引入 `agent-teams`，必须先补充项目级文档与决策。

## 阻塞关系

- `DEV-001` 阻塞全部后续阶段。
- `DEV-002` 阻塞所有涉及持久化的业务阶段。
- `DEV-003` 阻塞所有涉及角色、资源归属和审计的业务阶段。
- `DEV-004` 阻塞题库、组卷、考试、视频解释来源链路。
- `DEV-005` 阻塞考试主链路。
- `DEV-006` 阻塞分析与视频最小闭环。
- 前端泳道不被 `DEV-008` 阻塞，但真实三角色闭环只在 `DEV-008` 统一判断。
- `DEV-009` 与 `DEV-010` 决定能否稳定进入阶段 5。

## 与仓库现状的关系

- 本路线图是阶段 4 的权威规划口径。
- 即使仓库中已经出现 `backend/` 或其他早期实现，也不改变路线图顺序。
- 是否开始某个 DEV 阶段，以门禁判断和用户明确批准为准。
