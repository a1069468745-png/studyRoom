## 测试分层

| 测试层级 | 目标 | 覆盖范围 | 执行时机 | 是否进入 CI |

## 回归策略

### 什么时候跑回归测试

- 每完成一个 DEV 阶段后回归其依赖链主路径。
- 每次修改数据结构、权限规则或 API 契约后立即回归受影响阶段。
- 每次更新 mock/stub 或接口调用层后，立即执行契约测试与页面集成冒烟。
- 在 DEV-009、DEV-010 进行阶段 4 综合回归。

### 每个阶段需要回归哪些功能

| 开发阶段 | 需要回归的功能 | 回归方式 |
|---|---|---|
| DEV-001 | 服务启动、健康检查、通用错误结构 | 聚合构建 + 集成测试 |
| DEV-002 | 从空库初始化、核心约束、课程树层级 | 建库初始化测试 |
| DEV-003 | 登录、角色、资源归属、审计 | 权限测试 |
| DEV-004 | 知识点导航、题目入库约束 | 集成测试 |
| DEV-005 | 模板治理、范围解析、降级提示 | 单元 + 集成测试 |
| DEV-006 | 考试提交、判分、步骤展示 | 集成测试 |
| DEV-007 | 分析结果、视频可见性与审核 | 集成 + 权限测试 |
| DEV-008 | 三角色端到端主链路、mock/真实接口差异关闭 | E2E + 契约回归 |
| DEV-009 | 越权、异常、幂等和任务失败场景 | 回归测试 |
| DEV-010 | 发布前核心链路总回归 | 最终回归 |

### 哪些测试必须进入 CI

- 聚合构建与单元测试。
- 契约测试与 mock 一致性检查。
- 建库初始化测试。
- 服务级集成测试。
- 权限回归测试。
- DEV-008 之后的 E2E 冒烟测试。

### 哪些测试可以人工执行

- 视频审核、发布与播放体验。
- 管理员复杂操作流程。
- 发布清单、回滚方案和已知问题抽检。
