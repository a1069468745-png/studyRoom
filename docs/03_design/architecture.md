## 1. 架构概览

系统采用微服务架构，按业务域拆分服务，通过网关统一入口，通过 Nacos 管理注册与配置，通过 OpenFeign 进行服务间调用。

### 核心服务

- `gateway`：统一入口、路由、鉴权前置、限流
- `auth-service`：登录、会话、令牌、角色与资源权限
- `knowledge-service`：知识点、教材版本、内容管理
- `question-service`：题目、标签、解析、审核
- `paper-service`：组卷规则、试卷生成、模板版本
- `exam-service`：考试计划、考试实例、答卷
- `grading-service`：客观题判分、主观题批改、人工复核
- `analytics-service`：成绩分析、错题、知识点掌握
- `audit-service`：审计日志、操作留痕、发布追踪
- `job-service`：异步任务、重试、状态跟踪
- `file-service`：文件、图片、视频资源

## 2. 部署形态

### 首阶段

- 逻辑上是微服务，物理上可以先在同一台机器或同一网络内部署多个服务进程
- 每个服务独立进程、独立配置
- 同一 MySQL 集群内按服务独立 schema 或 database 管理
- Redis 用于缓存、幂等键和轻量任务协调
- MinIO 用于文件、图片、视频资源
- 手工备份

### 后续演进

- 支持容器化部署
- 支持水平扩容
- 支持定时备份
- 支持容灾与升级窗口
- 支持拆包/拆模块部署
- 支持独立服务灰度与回滚

## 3. 请求链路

### 3.1 知识点查询

前端 -> 网关 -> 知识库服务 -> 数据库/缓存 -> 返回结果。

### 3.2 组卷

前端提交规则 -> 网关 -> 组卷服务 -> 规则校验 -> 异步创建组卷任务 -> 后台 worker 计算试卷 -> 落库 -> 前端轮询/查询任务状态。

### 3.3 考试与批改

考试计划创建 -> 考试服务 -> 生成考试实例 -> 学生作答 -> 交卷 -> 批改服务 -> 分析服务 -> 结果展示。

### 3.4 视频资源

视频草稿生成 -> 审核 -> 发布 -> MinIO 存储 -> 学生端在线播放/离线缓存。

## 4. 设计取舍

### 方案 A：微服务

优点：

- 边界清晰
- 未来容器化和水平扩容成本低
- 业务域可独立演进

缺点：

- 首版运维复杂度高于单体
- 分布式事务和调用治理需要提前约束

### 方案 B：前后端分离的单体

优点：

- 接口边界清晰
- 前后端并行开发方便

缺点：

- 未来从单体改微服务的改造量大
- 分布式边界后补会导致测试场景扩散

### 方案 C：模块化单体

优点：

- 兼顾可维护性和交付速度
- 未来可平滑拆分
- 更适合当前并发和规模预期

缺点：

- 未来仍要经历单体拆分
- 迁移到微服务时改造量仍然大

推荐：方案 A。

## 5. 错误与降级

- 组卷失败时返回任务失败状态和可读原因。
- 历史真题不足时自动降级，不允许静默失败。
- 批改无法自动判定时进入人工复核队列。
- 视频资源不可用时返回可追踪错误并记录审计。
- 微服务之间调用必须带 `traceId` 和幂等标识。
- 分布式调用失败时，优先返回可恢复错误而不是隐式重试风暴。

## 6. 约束

- 统一鉴权。
- 服务间调用需要服务身份校验和最小权限。
- 审计日志不可修改，仅追加。
- 软删除默认启用，但关键业务删除需记录操作人和原因。
- 关键链路必须可追踪到用户、时间、资源和结果。
