## 1. 安全目标

- 保证内容与考试数据安全。
- 保证审核链路可追踪。
- 保证敏感数据不被未授权访问。
- 保证本地部署下的数据加密与传输加密。
- 保证微服务之间的身份认证、调用追踪和最小权限。

## 2. 认证与授权

- 统一登录认证。
- 采用角色 + 资源归属 + 审核流的权限模型。
- 管理员拥有全局管理权限。
- 老师仅能访问授权范围内的班级、题库和分析数据。
- 学生仅能访问自己的考试、成绩与学习内容。
- 服务间调用使用独立服务身份，不复用前端用户令牌直通所有后端服务。

## 3. 数据保护

### 3.1 传输加密

- 所有外部请求通过 HTTPS。
- 内部调用如跨进程，默认保留 TLS 方案扩展能力。
- 网关负责统一入口校验，服务间调用保留签名、服务令牌或后续 mTLS 扩展空间。

### 3.2 存储加密

- 本地存储至少对数据库备份、文件资源和敏感配置进行加密保护。
- 密钥不得写入代码仓库。

### 3.3 脱敏

- 日志中不得输出明文密码、令牌、身份证号等敏感数据。
- 对用户标识、手机号、邮箱等按需要脱敏展示。

## 4. 审计与留痕

- 登录、登出、审核、批改、发布、删除、导出均写审计日志。
- 审计日志仅追加，不可修改。
- 审计日志至少记录：操作者、时间、资源、动作、结果、来源 IP、traceId。
- 微服务链路中的 `traceId` 必须贯穿网关、业务服务和异步任务。

## 5. 软删除策略

- 核心业务表采用软删除。
- 删除操作需记录操作者和原因。
- 审计视图默认屏蔽已删除记录，管理端可按权限查看。

## 6. 高风险链路

### 6.1 题库审核

- 审核通过前不可对普通老师/学生开放。
- 审核状态变化必须留痕。

### 6.2 考试提交

- 防重复提交。
- 防越权访问他人考试。
- 检查考试窗口和迟到规则。

### 6.3 视频资源

- 未审核通过的视频仅管理员与审核人可见。
- 已发布视频支持离线观看，但必须受权限控制。

## 7. 安全风险

- 个人数据泄露风险。
- 本地部署下密钥管理风险。
- 审计日志过大导致存储膨胀风险。
- 视频离线缓存被非授权拷贝风险。
- 微服务配置中心或注册中心误配置导致的全局故障风险。
