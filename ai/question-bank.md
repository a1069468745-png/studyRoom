# question-bank.md

## 使用规则

Agent 在每个阶段开始时，必须先阅读本文件。

Agent 不能一次性抛出过多问题。  
推荐每次提出 5-8 个最关键问题。

问题必须服务于当前阶段目标，不得提前跳到后续阶段。

如果用户无法回答，Agent 必须：
- 标记为 TODO
- 记录到 assumptions.md 或 risk-register.md
- 不得自行编造答案

---

# 阶段 1：需求调研阶段

## 目标

明确用户是谁、问题是什么、为什么值得做。

## Agent 必须提出的问题

### A. 项目背景

1. 这个项目要解决什么问题？
2. 这个问题现在是如何被解决的？
3. 为什么现在要做这个项目？
4. 如果这个项目不做，会有什么损失？
5. 这个项目是内部工具、商业产品，还是实验项目？

### B. 用户与场景

1. 谁是主要用户？
2. 谁是次要用户？
3. 用户在什么场景下会使用它？
4. 用户现在最大的痛点是什么？
5. 用户使用频率大概是多少？
6. 用户是否愿意为这个解决方案付费或投入时间？

### C. 业务目标

1. 项目成功的标准是什么？
2. 你希望 1 个月后看到什么结果？
3. 你希望 3 个月后看到什么结果？
4. 有没有必须达成的业务指标？
5. 有没有明确不能做的事情？

### D. 约束条件

1. 时间限制是什么？
2. 团队人数和能力边界是什么？
3. 技术栈有没有限制？
4. 成本预算有没有限制？
5. 是否有合规、安全、隐私要求？

## 本阶段产出文档

- docs/01_research/research-plan.md
- docs/01_research/pain-points.md
- docs/00_project/assumptions.md
- .ai/context.md

## 进入下一阶段的条件

- 已明确目标用户
- 已明确核心问题
- 已明确核心场景
- 已区分事实、假设和待验证问题
- 已形成初步需求调研结论

# 阶段 2：产品定义阶段

## 目标

把“想法”变成“可开发、可验收的产品定义”。

## Agent 必须提出的问题

### A. MVP 范围

1. 最小可用版本必须包含哪些功能？
2. 哪些功能可以暂缓？
3. 哪些功能明确不做？
4. 如果只能做 3 个功能，应该是哪 3 个？
5. 用户完成核心任务的最短路径是什么？

### B. 用户故事

1. 每类用户分别要完成什么任务？
2. 用户完成任务前需要什么条件？
3. 用户完成任务后应该看到什么结果？
4. 有没有异常路径？
5. 有没有管理员、运营、审核员等后台角色？

### C. 验收标准

1. 每个功能怎么算完成？
2. 成功状态是什么？
3. 失败状态是什么？
4. 边界情况有哪些？
5. 哪些行为必须被禁止？

### D. 指标

1. 产品上线后看什么指标？
2. 用户激活指标是什么？
3. 留存或复用指标是什么？
4. 转化指标是什么？
5. 质量指标是什么？

## 本阶段产出文档

- docs/02_product/prd.md
- docs/02_product/user-stories.md
- docs/02_product/acceptance-criteria.md
- docs/02_product/metrics.md
- .ai/specs.md

## 进入下一阶段的条件

- MVP 范围清楚
- 每个功能有验收标准
- 非目标范围明确
- specs.md 已更新
- 没有严重产品定义冲突

# 阶段 3：方案设计阶段

## 目标

把产品需求转成技术方案，明确系统边界、数据结构、接口和关键决策。

## Agent 必须提出的问题

### A. 架构问题

1. 这是单体应用、前后端分离，还是多服务架构？
2. 是否需要用户系统？
3. 是否需要权限系统？
4. 是否需要后台管理？
5. 是否需要第三方服务集成？
6. 是否有实时性要求？
7. 是否有离线能力要求？

### B. 数据问题

1. 核心实体有哪些？
2. 实体之间是什么关系？
3. 哪些数据需要持久化？
4. 哪些数据是临时状态？
5. 哪些字段是敏感数据？
6. 是否需要审计日志？
7. 是否需要软删除？

### C. API 问题

1. 前端需要哪些接口？
2. 每个接口的输入是什么？
3. 每个接口的输出是什么？
4. 失败时返回什么错误？
5. 是否需要分页、筛选、排序？
6. 是否需要限流？
7. 是否需要幂等？

### D. 技术选型

1. 默认技术栈是什么？
2. 是否允许引入新框架？
3. 是否允许引入第三方 SDK？
4. 是否需要数据库迁移工具？
5. 是否需要缓存？
6. 是否需要消息队列？
7. 这些选择的替代方案是什么？

## 本阶段产出文档

- docs/03_design/solution-design.md
- docs/03_design/architecture.md
- docs/03_design/data-model.md
- docs/03_design/api-spec.md
- docs/03_design/security-design.md
- .ai/decisions.md
- .ai/risk-register.md

## 进入下一阶段的条件

- 架构边界明确
- 数据模型明确
- API 规格明确
- 关键技术决策已写入 decisions.md
- 主要风险已记录
- 没有未解释的技术复杂度

# 阶段 4：技术开发阶段

## 目标

按照已确认的设计小步实现，先计划，再测试，再编码。

## Agent 必须提出的问题

### A. 实现计划

1. 当前任务对应 specs.md 的哪一部分？
2. 需要修改哪些文件？
3. 需要新增哪些文件？
4. 是否影响已有接口？
5. 是否影响已有数据结构？
6. 是否需要迁移？
7. 是否需要更新文档？

### B. 测试问题

1. 这个功能应该先写哪些测试？
2. 正常路径测试是什么？
3. 异常路径测试是什么？
4. 边界条件是什么？
5. 是否需要集成测试？
6. 是否需要 E2E 测试？
7. 如何证明功能完成？

### C. 实现边界

1. 本次任务只做什么？
2. 本次任务不做什么？
3. 哪些地方不能改？
4. 哪些技术债可以接受？
5. 哪些技术债必须立即处理？

## 本阶段产出文档

- docs/04_development/implementation-plan.md
- docs/04_development/task-breakdown.md
- docs/04_development/coding-notes.md
- 测试文件
- 更新 .ai/specs.md
- 必要时更新 .ai/decisions.md

## 进入下一阶段的条件

- 功能实现完成
- 测试通过
- 文档同步
- 没有未记录的行为变化
- 没有绕过 specs.md 的实现

# 阶段 5：测试验证阶段

## 目标

验证功能是否真的满足规格，而不是只看代码是否能运行。

## Agent 必须提出的问题

### A. 测试覆盖

1. 所有验收标准是否都有测试？
2. 核心用户路径是否覆盖？
3. 失败路径是否覆盖？
4. 权限场景是否覆盖？
5. 数据异常场景是否覆盖？
6. 并发或重复提交是否覆盖？
7. 兼容性场景是否覆盖？

### B. 缺陷分析

1. 当前有哪些已知 bug？
2. 哪些是阻塞问题？
3. 哪些是非阻塞问题？
4. bug 的根因是什么？
5. 是否补充了回归测试？
6. 是否存在同类问题？
7. 是否需要更新风险登记？

### C. 验证证据

1. 运行了哪些测试命令？
2. 测试结果是什么？
3. 有没有截图、日志或报告？
4. 有没有人工验证步骤？
5. 有没有无法验证的部分？

## 本阶段产出文档

- docs/05_testing/test-plan.md
- docs/05_testing/test-cases.md
- docs/05_testing/regression-checklist.md
- docs/05_testing/bug-report.md
- docs/05_testing/verification-report.md

## 进入下一阶段的条件

- 核心路径验证通过
- P0/P1 问题已解决
- 回归测试通过
- 无法自动化的测试已有人工验证步骤
- 验证证据完整

# 阶段 6：质量审计阶段

## 目标

从需求、代码、测试、安全、性能、文档一致性角度做发布前审计。

## Agent 必须提出的问题

### A. 需求一致性

1. 实现是否完全符合 specs.md？
2. 是否有未实现的验收标准？
3. 是否有超出范围的功能？
4. 是否有需求被误解？
5. 是否有文档和代码不一致？

### B. 代码质量

1. 是否有重复实现？
2. 是否有过大的函数或文件？
3. 是否有难以维护的逻辑？
4. 是否有未处理的异常？
5. 是否有临时代码？
6. 是否有 TODO 没有记录到风险或任务中？

### C. 安全审计

1. 是否处理了用户输入校验？
2. 是否有权限绕过风险？
3. 是否泄露敏感信息？
4. 是否有硬编码密钥？
5. 是否有日志泄露？
6. 是否有依赖安全风险？

### D. 性能审计

1. 是否存在明显慢查询？
2. 是否有重复请求？
3. 是否有不必要的大对象加载？
4. 是否有缓存需求？
5. 是否有分页需求？
6. 是否有资源泄露风险？

### E. 发布判断

1. 是否可以发布？
2. 如果有条件发布，条件是什么？
3. 如果暂缓发布，阻塞项是什么？
4. 发布后需要监控什么？
5. 回滚方案是什么？

## 本阶段产出文档

- docs/06_quality/quality-audit.md
- docs/06_quality/security-review.md
- docs/06_quality/performance-review.md
- docs/06_quality/release-checklist.md
- docs/06_quality/release-decision.md

## 阶段完成条件

发布结论必须是以下三种之一：

- 可以发布
- 有条件发布
- 暂缓发布

不得输出模糊结论。
